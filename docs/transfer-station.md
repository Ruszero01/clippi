# 文件中转站（Transfer Station）

## 1. 目标

文件中转站复用 Clippi 已配置的本地文件夹或 WebDAV 后端，为不同设备提供临时文件上传、查看、下载和删除能力，对应 Issue #41。

发布版本必须满足：

- 所有网络、文件读取、哈希和中转站数据库操作均在后台线程执行，不阻塞 GPUI 主线程。
- 远端协议不保存任何设备的完整本地路径，只保存可跨 Windows/macOS 使用的文件名。
- 多设备同时上传或删除时不能静默覆盖对方的清单更新。
- 下载完成后校验 SHA-256 和文件大小，拒绝损坏或被篡改的 blob。
- 中转站协议与剪贴板同步协议完全独立，文件条目仍不进入 clippi_sync.json。

当前版本仅支持单文件上传。多文件和目录必须在 UI 层明确拒绝，不能静默只处理第一项。

## 2. 用户流程

1. 在“设置 → 同步”中配置并启用至少一个后端。
2. 在对应后端卡片中选择“中转后端”。
3. 开启“文件中转站”，选择永久保留或 1/3/7/30 天自动过期。
4. 在普通剪贴板列表右键单个文件，选择“上传到中转站”。
5. 点击标题栏文件图标进入中转站视图。
6. 云端条目可以下载；已具有有效本地文件的条目可以打开位置或复制路径；所有条目均可在确认后从中转站删除。

标题栏入口只由“文件中转站”功能开关控制：功能开启时始终显示，关闭时隐藏；不依赖后端可用状态、clippi_files.json 是否存在或清单条目数量。后端不可用时点击入口应给出配置提示，不进入无效视图。

中转视图中的本地条目使用 iconfont 的 `&#xe794;`，纯云端条目使用 `&#xe601;`，不得为纯云端条目触发通用文件图标缓存或显示“文件丢失”状态。

## 3. 远端布局

~~~
<backend root>/
├── clippi_sync.json        # 原有剪贴板同步协议
├── clippi_files.json       # WebDAV 清单 / 本地文件夹 v1 只读迁移基线
├── file_ops/               # 本地文件夹 v2 不可覆盖操作日志
│   └── <uuid>.json         # 含 Lamport 逻辑时钟
└── files/
    └── <blob_id>           # 每次上传独立的不可变 blob
~~~

blob 路径不包含原始文件名、扩展名或本地目录。`blob_id` 由内容 SHA-256 和随机 UUID 组成，避免删除旧上传与并发重传争用同一对象。原始文件名只存在于清单元数据中。

## 4. 清单协议

~~~json
{
  "version": 2,
  "device_name": "Home-PC",
  "updated_at": "2026-07-20T02:30:00Z",
  "files": [
    {
      "hash": "64-character-lowercase-sha256",
      "blob_id": "<sha256>-<uuid>",
      "name": "report.pdf",
      "ext": "pdf",
      "size": 1048576,
      "uploaded_at": "2026-07-20T02:30:00Z",
      "expires_at": "2026-07-23T02:30:00Z",
      "uploaded_by": "Home-PC"
    }
  ]
}
~~~

字段约束：

- hash：恰好 64 个十六进制字符，是 blob 内容的 SHA-256。
- blob_id：本次上传的不可变远端对象键；v1 条目缺失时兼容回退到 hash。
- name：单个文件名，不得包含目录分隔符、控制字符或 Windows 非法字符；不得以空格或点结尾；拒绝 CON、NUL、COM1 等 Windows 保留名。
- ext：仅作显示和兼容元数据，不参与远端 blob 定位。
- size：原始文件字节数，下载时必须复核。
- uploaded_at、expires_at：RFC3339 UTC 时间。永久保留时 expires_at 为空。
- 高于客户端支持版本的清单只读失败，旧客户端不得回写未知新版本。

## 5. 本地缓存和路径规则

下载文件保存为：

~~~
<Clippi data>/file_cache/<sha256>/<portable file name>
~~~

路径规则：

- 远端清单永不保存完整本地路径。
- SQLite 中的 FileData.path 是当前设备的本地状态，只用于打开文件和写入系统剪贴板，不参与任何远端同步。
- “本地”状态由 DB 中匹配的隐藏 transfer 关联记录决定；清单刷新不重复探测 FileData.path，路径失效由统一的本地 DB 条目维护流程处理，避免云盘占位文件、离线卷或网络路径阻塞刷新。
- 用户在中转视图手动删除条目时只删除远端清单和 blob；已下载到 file_cache 的文件转为普通本地文件记录，用户上传时的原始文件也不受影响。自动过期维护仍可清理对应的中转缓存。
- 所有来自清单的 hash、name 和 ext 必须先验证，再参与 URL 或 PathBuf 拼接。

## 6. 清单并发控制

WebDAV 的 `clippi_files.json` 是共享状态，不能使用无条件的“拉取—修改—覆盖”；本地文件夹后端则以不可变操作日志作为共享状态。

每次变更遵循：

1. 拉取清单及 revision。
2. 验证协议版本和所有条目。
3. 在内存中应用变更。
4. 使用 expected revision 条件写入。
5. 若发生冲突，重新拉取、重新合并并重试，最多 5 次。

后端实现：

- WebDAV：使用 ETag + If-Match；首次创建使用 If-None-Match: *。服务端不提供 ETag 时允许只读展示，但拒绝不安全的覆盖写入。
- 本地文件夹：每次清单变更写入 `file_ops/<uuid>.json` 原子操作文件。各设备只创建唯一文件，拉取时按 `(Lamport 逻辑时钟, uuid)` 确定性折叠全部操作，因此不依赖 Windows 与 Mac 系统时钟一致；OneDrive/iCloud/Dropbox 也无需提供跨设备文件锁，不会因同名清单覆盖而丢更新。每次拉取都会立即尝试解析 `clippi_files.json` 及云盘生成的所有 `clippi_files*.json` 冲突副本，完整快照按 hash 合并为迁移基线，尚未写完整的 JSON 留待下次轮询重试，再由操作日志执行权威的 upsert/delete；成功写回规范清单后只清理已稳定且验证有效的冲突副本。

临时文件替换必须具有跨平台覆盖语义：Unix 使用同卷 rename，Windows 使用 MoveFileExW + MOVEFILE_REPLACE_EXISTING，避免第二次写入因目标已存在而失败。

网络或解析失败绝不能退化为空清单后覆盖服务器。

## 7. 后台运行模型

GpuiTransferService 由 WindowManager 持有，沿用统一 200ms GPUI poll loop 收集结果，但阻塞工作全部由单独工作线程完成。

AppState 只保存：

- transfer_filter_active：是否显示中转站视图。
- transfer_entries：最近一次已验证的清单快照及本地状态。
- pending_transfer_commands：等待后台执行的 Refresh、Upload、Download、Delete、Cleanup 命令。
- transfer_busy：当前是否有任务运行。

运行时保证同一时刻只有一个远端中转命令，避免本机上传、删除和清理互相覆盖。进入中转视图时立即拉取清单，并仅为这次进入刷新显示全局加载指示；主窗口可见且正在显示中转列表期间，每 2 秒静默轻量轮询一次清单，不显示转圈。窗口隐藏或显示其他列表时不自动刷新列表，只有上传等用户命令仍会访问后端。刷新间隔从上一次任务完成时计算，避免慢请求完成后立即重复；拉取结果与当前解析列表一致时不替换或重建列表。首次刷新分两阶段发布：清单解析和 DB 关联对账完成后立即展示列表，不访问普通文件路径；普通剪贴板文件的内容哈希匹配在独立后台任务中补全，且旧任务结果不得覆盖更新的清单状态。过期清理由现有缓存维护调度器每天在后台触发一次，与列表是否可见无关。

## 8. 操作和失败语义

### 上传

1. 验证单个普通文件和便携文件名。
   当前版本单文件上限为 512 MiB，超过限制在读取或下载前拒绝。
2. 后台以固定大小缓冲区流式读取文件并计算 SHA-256 和本地内容哈希，不把整个文件载入内存。
3. 再次流式读取并上传 blob，同时复核长度、SHA-256 和文件元数据；文件在上传期间变化时删除不完整 blob 并失败。
4. 通过条件写入把条目合并进最新清单。
5. 写入本地 transfer DB 条目，本地路径指向原始文件。

清单拉取失败时上传失败，不得创建空清单覆盖远端。

### 下载

1. 验证清单条目。
2. 将 blob 直接流式写入 file_cache/<hash>/ 下的唯一临时文件，不在内存中保留完整内容。
3. 写入过程中同步计算并校验字节数和 SHA-256，随后刷新并同步临时文件。
4. 校验成功后原子替换为 file_cache/<hash>/<name>。
5. 更新本地 DB，主线程刷新视图并把文件引用写入系统剪贴板。

完整性校验失败时不落盘、不写 DB。

### 删除

1. 用户确认删除。
2. 先从最新清单中条件删除条目。
3. 再删除远端 blob。
4. 解除本地 transfer 关联但不删除本地文件；已下载缓存转为普通文件记录，上传来源继续保留原始文件。

清单更新失败时保留 blob 和本地状态并向用户报错，不能显示伪成功。

### 自动过期

- 上传时根据当时设置写入 expires_at。
- 清理条件是 expires_at 小于等于当前 UTC 时间。
- 旧条目若没有 expires_at，可使用 uploaded_at + 当前保留天数兼容计算。
- 0 表示永久保留，不执行自动清理。

## 9. UI 数据模型

中转站视图由远端清单临时生成 ClipboardItem 兼容卡片，但使用基于 SHA-256 生成的稳定负 ID，与 SQLite 正 ID 隔离。

专用动作只在中转站视图出现：

- 云端：下载、从中转站删除。
- 本地：打开文件位置、复制本地路径、从中转站删除。
- 云端条目双击触发下载；本地条目双击打开所在位置。
- 下载任务入队后，条目状态标签立即切换为带旋转指示的“下载中”，并阻止同一条目重复入队；成功后切换为“本地”，失败后恢复为“云端”。
- 状态标签统一使用浅灰描边；云端及下载中使用蓝色文字，本地使用绿色文字。
- 普通剪贴板文件条目的中转标签是清单驱动的派生状态：后台刷新清单时，以远端文件大小预筛本地候选，再流式计算本地文件 SHA-256；内容哈希存在于当前清单时显示仅含云端图标（U+E794）的浅灰描边标签。上传动作不得直接给来源条目写标记。
- 派生判定只使用文件内容哈希，不使用完整本地路径或文件名作为跨设备身份；路径、大小和修改时间仅用于本机哈希缓存。这样当前版本下载产生的普通条目、旧版本上传的条目以及其他设备上传的同内容文件都会在刷新后补全标签。
- 手动删除、到期清理或其他设备移除云端条目后，清单刷新会重新校准并移除普通条目的标签；本地文件缺失、目录、多文件条目或内容不匹配时也不显示标签。
- 用户删除普通 DB 本地文件条目时，同路径的隐藏 transfer 关联一并移除，内存中的中转项立即从本地状态切换为云端状态；不删除磁盘文件或远端对象。
- 中转站多选使用独立操作域：右键菜单、悬浮工具栏和 Delete 键只允许批量从中转站删除，不得调用普通剪贴板的粘贴、合并、标签、收藏或数据库删除操作。

所有列表刷新必须调用 AppState.visible_items()，不得在中转站激活时无条件回退到普通剪贴板 items。

普通列表中的本地 transfer DB 条目仍按普通文件处理，不依赖未加载的远端清单执行删除。

## 10. 发布验证

最低测试矩阵：

- 文件名：中文、空格、多点扩展名、无扩展名、Windows 保留名、路径穿越。
- 完整性：hash 不匹配、size 不匹配、损坏 JSON、高版本清单。
- 并发：两个客户端同时上传、上传与删除冲突、连续冲突超过重试上限。
- 生命周期：永久、1/3/7/30 天、旧条目无 expires_at。
- 状态：原始文件被外部删除、缓存被删除、后端切换、后端禁用。
- UI：空站入口、普通/中转视图刷新、专用右键菜单、悬浮工具栏、删除确认、双击行为。
- 后端：本地文件夹和 WebDAV 的首次创建、条件更新、404、401/403、409/412。

发布前必须通过 cargo fmt --check、cargo test 和 cargo clippy --all-targets --all-features -- -D warnings。
